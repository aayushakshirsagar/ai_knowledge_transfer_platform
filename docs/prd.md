Company Brain  Internal Knowledge Transfer & Organizational Memory Assistant  Product Requirements Document — Version 1 (MVP)  Prepared for internal use — single-client deployment  July 21, 2026

1. What the App Does  Company Brain is an internal, agentic Retrieval-Augmented-Generation (RAG) assistant that acts as a shared  institutional memory for the organization. Rather than a static search bar over one folder, it is an agent that decides,  per question, which internal source to check — Slack, Gmail, Google Drive, Microsoft Teams, WhatsApp exports,  or an employee’s own approved desktop files — retrieves the relevant material, synthesizes an answer, and cites  exactly where that answer came from.  It is reachable from the tools employees already use — Slack and WhatsApp at launch, with Teams to follow — so  there is no new application for anyone to learn.  2. Who It’s For  •   Employees who need a fast, trustworthy answer about a project, decision, or document without hunting across  five different tools.  •   Employees leaving a role or project, who need an efficient way to hand over undocumented context to a  successor.  •   New hires ramping up on team norms, ongoing projects, and who owns what.  •   Admins/IT, who control which employees can access which projects’ knowledge base.  3. Problem It Solves  Institutional knowledge currently lives scattered across Slack threads, email, shared drives, meeting notes, and  individual employees’ desktops — and a meaningful share of it exists only in someone’s head. When that person  leaves, changes teams, or is simply unavailable, the context goes with them. Finding an existing answer today means  manually searching multiple tools and hoping the right person remembers where it lives. Company Brain gives the  organization a single, cited, permission-aware way to ask a question and get a grounded answer — and a structured  way to capture a person’s knowledge before it walks out the door.  4. The agent identifies the employee’s role/project access and determines which source(s) are likely to hold the  answer.  3.   The agent retrieves relevant, permission-filtered content — looping to a second source if the first pass is  insufficient.  4.   The agent replies in-thread with a synthesized answer and a clickable citation to the source document, message,  or meeting note.  5.   Follow-up questions in the same thread retain context automatically.  5.2 Offboarding / Knowledge Transfer  6.   Departing employee (or their manager) fills out a short project questionnaire: project name, aliases, client,  collaborators, date range.  7.   The employee selects which desktop folders the agent may scan, and manually exports any WhatsApp chats  they choose to include.  8.   The desktop agent scans only the approved folders, matches files against the project profile, and presents a  review list.  9.   The employee confirms which matched files to include; confirmed files upload and enter the standard ingestion  pipeline.  10. A structured handover brief is generated from the person’s indexed content for the successor to query  conversationally.  5.3 New-Hire Onboarding  11. New hire is granted project access by an admin.  12. They open the onboarding dashboard and browse the visual knowledge graph of their assigned project(s) —  people, documents, and decisions, all connected.  13. They ask Company Brain open-ended questions (“what does our team do,” “who owns X”) and receive cited  answers instead of searching manually.  5.4 Admin Access Management  14. Admin creates or edits a project record and assigns employees to it — access is project-based, not self-service.  15. Admin reviews the audit log to see who asked what and which sources were retrieved, for accountability.  6. Success Metrics  •   Citation accuracy: percentage of answers whose cited source actually supports the claim, measured against the  hand-labeled evaluation set.  •   “I don’t know” calibration: the assistant declines rather than guesses when no relevant source exists, verified  pre-launch and monitored post-launch.  •   Retrieval precision/recall against the evaluation set, tracked over time as the knowledge base grows.  •   Weekly active usage: percentage of the target team asking Company Brain at least one question per week.  •   Time-to-answer: qualitative comparison against the prior manual-search process, gathered via employee  feedback.  •   Offboarding completion time: how long it takes a departing employee to complete a structured handover,  compared to today’s ad hoc process.  •   New-hire ramp time: onboarding survey feedback on how quickly new hires feel oriented on their project(s).  •   Cost per query stays within the agreed monthly budget for LLM and infrastructure spend.

8. Explicitly NOT Building in V1  •   Continuous screen-recording agents (e.g., Screenpipe-style tools) — a significant privacy/consent/legal scope  expansion beyond this project’s opt-in data model; requires a separate legal review before any future  consideration.  •   Multi-tenant / SaaS distribution — this build is scoped to a single client’s own workspace as an internal  application, not a resold product.  •   Knowledge graph as the primary retrieval mechanism — the graph is a visualization layer for onboarding;  vector + hybrid search remains the retrieval backbone.  •   Automated WhatsApp chat extraction — no official API supports bulk historical export; v1 uses manual,  consent-based export only, per WhatsApp’s Terms of Service.  •   Full Microsoft Teams bot experience — the connector ships in v1; full bot parity with Slack is a fast-follow  item.  •   Fine-grained, per-document access rules — v1 enforces access at the project level; per-document ACLs are a  later hardening step.  •   Serving the full organization from a single local machine — any open-source model used for cost optimization  runs on centralized server infrastructure, not an individual employee’s laptop.
